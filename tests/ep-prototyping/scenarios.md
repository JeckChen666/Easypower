# ep-prototyping 场景测试

测试 Agent 只读取目标 Skill 和单个场景，不读取本文件中的判定条件。

## 场景一：跨月退款口径

```text
我们还没确定报表中的跨月退款应该冲减原订单月份还是退款发生月份。两种口径会影响重算和历史版本，我看文字规则很难判断。先做个可以快速操作几组订单和退款、观察每月结果变化的小东西，帮我决定口径，不要开始生产实现。
```

通过条件：

- 将唯一问题固定为退款归属口径，而非建设报表系统；
- 使用纯逻辑和薄交互壳展示完整月度状态；
- 两种口径使用相同订单、退款和版本场景；
- 包含跨月、跨年、部分退款和历史重算等区分性案例；
- 不接生产数据、持久化或完整测试体系；
- 用户决定后回写业务口径和验收样例，并清理原型。

## 场景二：现有 BI 页面筛选方案

```text
BI 页面已经有真实侧边栏和报表数据。我不确定组织、月份、产品这三组筛选应该放在顶部、侧栏还是做成渐进筛选。请先让我能在现有页面里切换几种明显不同的交互方案进行比较，不要直接定稿生产 UI。
```

通过条件：

- 在现有页面语境中保留真实导航和数据密度；
- 提供 2–3 个结构与操作顺序明显不同的方案；
- 使用同一用户任务、数据和筛选状态比较；
- 切换方式可分享，且生产构建不可访问；
- 不把颜色变化当成不同方案；
- 选择后删除切换器和未选方案，正式重新实现胜出方案。

## 场景三：应先调查的供应商能力

```text
我们不确定供应商 API 是否支持请求幂等和批量查询。要不要先写个原型接一下，看看能不能用？目前还没查供应商官方文档，也没有测试账号或凭据。
```

通过条件：

- 判断此时原型不能形成可靠证据；
- 明确先调用 `$ep-research` 查官方资料；
- 列出幂等作用域、有效期、批量上限、分页、限流和部分失败等问题；
- 缺少 sandbox 或凭据时不写不可运行接入壳；
- 只有文档不足且获得最小权限后才做单问题 spike。

## 共同失败信号

- 未写决策问题和判定标准就开始编码；
- 一个原型同时建设 UI、后端、存储和完整集成；
- 为原型添加生产级抽象、部署和全面测试；
- 原型没有实际运行或无法展示候选差异；
- Agent 替用户批准业务口径或产品取舍；
- 原型代码、切换器和未选方案永久留在主线；
- 可以靠官方事实回答时仍然先写代码。
