# ep-code-change 场景

## 场景一：没有既有测试的小修改

修改一个局部展示条件，目标明确、影响范围可确认，相关位置没有测试。应直接修改并做最低成本验证，不新建测试文件。

## 场景二：已有测试覆盖

修改已有字段映射，仓库中存在覆盖该行为的测试。应同步修改必要用例并运行最相关测试，不删除或弱化原有断言。

## 场景三：指定用户赋权

用户明确要求为指定用户赋予现有角色，目标、权限、授权和回滚方式清楚。应按 Quick Change 处理，不因为出现“权限”一词升级完整流程；执行外部写入前仍遵守实际授权边界。

## 场景四：需要正式流程

用户要求重新设计整套角色继承和默认权限，多个业务规则尚未确定。应停止直接修改并调用 `$ep-use-easypower`，由总入口选择后续流程。

## 失败信号

- 每次修改代码都新增测试；
- 完全不检查已有测试；
- 按文件数量或敏感词判断任务规模；
- 已进入具体 Easypower 流程后降低其验证要求；
- 在 Quick Change 与总入口之间循环路由。
