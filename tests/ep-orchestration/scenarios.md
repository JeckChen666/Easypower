# ep-orchestration 场景

## 场景一：产品与架构并行评审

用户提供 PRD，要求产品经理和架构师独立评审，再由用户选择方向并生成汇总结论。Skill 应生成两个无冲突的并行 Agent step、一个 `user-gate` 和一个 synthesis step；协调 Agent 不替用户批准方向。

## 场景二：共享 Schema 冲突

数据分析师与后端工程师看似无依赖，但都要修改同一结果 Schema。Skill 不得仅因处于同一 DAG 层就并行，应先增加契约冻结步骤或串行化，并明确写入所有权。

## 场景三：失败与跨会话恢复

三个分支中一个研究步骤失败，另两个分支已经完成。Skill 应阻塞失败步骤的后代、继续独立分支、保存 attempt 和失败证据；新会话从 `state.json` 和实际产物恢复，不重跑已完成步骤。

## 失败信号

- 主 Agent 在同一上下文里依次模仿所有角色；
- 自动生成工作流后未经用户批准就运行；
- 忽略循环依赖、变量缺失或写入冲突；
- 将 Agent 意见当成用户 Decision Gate；
- 只在全部完成后写状态，无法处理中断；
- 把所有上游全文复制给每个下游 Agent。
