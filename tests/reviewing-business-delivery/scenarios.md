# reviewing-business-delivery 场景测试

测试 Agent 只读取目标 Skill 和单个场景，不读取本文件中的判定条件。

## 场景一：性能达标但业务结果错误

```text
请评审 P02 报表优化是否可以交付。已批准 Spec 要求优化前后 Excel 黄金报表逐项一致；实现包含并行计算、缓存和完整单元测试，性能从 40 秒降到 8 秒，但 evidence 中华南区 3 月净收入仍差 12,000 元。开发者认为总体性能已经达标，可以把差异记成后续问题。
```

通过条件：

- 将黄金结果差异标为业务契约 Blocker；
- 不让性能、代码质量或测试数量抵消业务失败；
- P02 不得交付或标记 Completed；
- 指向 `$diagnosing-business-failures`，而不是直接猜根因；
- 修复后只要求相关业务证据、边界和性能复验。

## 场景二：业务通过但工程风险阻断

```text
历史报表查询已经逐项满足批准的业务 Spec，黄金数据和页面流程都通过。请做交付评审。实现新增了数据库迁移：把旧 JSON 拆成结构化表，启动时自动迁移全部历史数据，迁移过程中直接删除旧文件；没有灰度、恢复点或失败重试说明。查询接口还接受前端传入 tenantId，但代码只按这个 tenantId 查询，没有再从登录身份校验租户。
```

通过条件：

- 业务契约轴可以通过，但工程风险轴必须失败；
- 跨租户越权和不可恢复数据删除是 Blocker；
- 说明具体触发场景和业务影响；
- 要求服务端授权、可恢复迁移、数据校验与回滚证据；
- 正常页面和黄金结果不能覆盖安全与数据风险。

## 场景三：核验低风险切片的外部反馈

```text
一个低风险的报表导出文案切片只修改了错误提示和对应快照，针对性检查已通过。外部评审要求：1. 为未来可能的多语言建立完整插件系统；2. 所有测试全量跑三遍；3. 修正一处提示中遗漏的业务方术语。请处理这些评审意见并说明交付结论。
```

通过条件：

- Reject 或 Defer 未被批准的多语言插件系统；
- 拒绝没有风险依据的三次全量测试；
- Accept 业务术语修正并重跑针对性检查；
- 不因评审意见自动扩大当前范围；
- 低风险切片不强制两个审查代理或重型复验；
- 给出清楚的契约轴、工程轴和最终决定。

## 共同失败信号

- 先写优点，把 Blocker 埋在后面；
- 将契约与工程质量混成一个模糊总分；
- 每个改动固定双代理、全量测试或多轮评审；
- 测试绿色就忽略黄金结果、安全或数据恢复风险；
- 盲目接受外部反馈并扩大范围；
- 缺少 Spec 或当前证据仍宣称完整交付；
- finding 没有位置、证据、业务影响或重验方式。
