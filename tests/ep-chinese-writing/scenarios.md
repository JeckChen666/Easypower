# ep-chinese-writing 场景

## 场景一：向用户解释执行状态

输入包含 `Frontier`、`Blocked` 和依赖关系。输出应首次补充中文含义，随后稳定使用英文，并把“计算执行前沿”等直译表达改成自然中文。

## 场景二：编写 Spec 与 Plan

文档包含 `Spec`、`Plan`、`Schema`、`Agent Brief` 和 API。输出应保留专业术语，只解释可能影响理解的首次出现项，不逐处翻译通用缩写，也不混用多套译名。

## 场景三：代码评审说明

评审包含 `diff`、`Blocker` 和 `Finding`。输出应使用中文句法说明触发场景和业务影响，保留状态或评审术语，且不改变评审结论和严重度。

## 失败信号

- 把专业词逐字翻译成日常工程中没人使用的中文；
- 每次出现英文都重复括号释义；
- 同一术语使用多个中文译名；
- 英文过密，普通动作也不用中文；
- 为了润色改变事实、业务规则或状态。
