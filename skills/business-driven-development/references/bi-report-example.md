# BI 报表示例

这个示例展示文档之间的职责边界，不是固定模板。

## Spec 摘要

```markdown
# 月度利润报表 Spec

## 业务目标
财务人员导入销售与成本数据后，获得口径一致、可追溯的月度利润报表。

## 核心业务闭环
**输入：** 已冻结的原始 Excel 样本。
**处理规则：** 按已确认的订单归属、成本分摊、退款和舍入口径计算。
**输出：** 月度利润明细与区域汇总。
**完成标志：** 生成结果与业务方目标样本在约定字段和精度上相同。

## 验收契约
- 金额按分精确比较，比例保留四位小数；
- 空值、退款跨月和重复订单按决策表处理；
- 禁止硬编码目标报表中的结果值；
- 后续增强不得改变相同输入下的业务结果。

## 增强能力
1. 在目标数据规模下缩短刷新时间；
2. 支持区域、月份筛选和稳定排序；
3. 保存结构化结果、输入版本和计算版本。
```

Spec 不描述先改哪个文件，也不把“性能更快”直接变成没有基线的数字。

## 主 Plan 摘要

```markdown
# 月度利润报表 Plan

## 业务切片
| ID | 业务结果 | 依赖 | 验收摘要 |
|---|---|---|---|
| P01 | 原始数据生成正确利润报表 | 无 | 黄金样本结果一致 |
| P02 | 大数据量下更快生成相同报表 | P01 | 结果等价且基准改善 |
| P03 | 用户筛选和排序报表 | P01 | 场景结果正确 |
| P04 | 结构化保存并可追溯查询 | P01 | 重放结果一致 |

## 执行前沿
P01

## 并行与所有权
P02、P03、P04 在 P01 后可并行探索；若它们共同修改计算接口或结果 Schema，先由主 Agent 固定契约再调度。
```

主 Plan 不提前详细设计 P02-P04，只固定交付结果和依赖。

## P01 子 Plan 中的决策代码

复杂分摊顺序仅靠文字容易产生不同实现，因此保留最小伪代码：

```text
net(order) = paid(order) - valid_refunds(order, report_month)

allocate(order, dimensions):
    weights = normalize_positive_weights(dimensions)
    shares = round_each(net(order) * weights, currency_scale)
    return assign_rounding_remainder(shares, largest_weight_first)
```

片段固定了净额、权重和舍入余差规则，但没有提前实现解析器、数据库访问或导出代码。

## P01 验收

```markdown
1. 使用冻结的原始 Excel 运行完整流程。
2. 比较利润明细、区域小计和总计。
3. 对差异输出业务字段、期望值、实际值和适用规则。
4. 使用第二组边界样例验证退款跨月、空权重和舍入余差。
5. 保存输入哈希、计算版本、结果和差异报告。
```

P01 通过后，P02 的子 Plan 才基于实际瓶颈选择并行、增量、缓存或算法优化；P03、P04 同样在进入执行前沿时展开。
