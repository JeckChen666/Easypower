# 渐进式 Plan 协议

Plan（执行计划）将已批准的 Spec 转换为可自主执行的业务切片和依赖图。主 Plan 管理全局，子 Plan 在进入 Frontier（当前可执行任务）时按需展开。

## 文件结构

```text
docs/easypower/<feature>/
├─ spec.md
├─ plan.md
├─ plans/
│  ├─ P01-core-loop.md
│  ├─ P02-<enhancement>.md
│  └─ P03-<enhancement>.md
└─ evidence/
```

默认最多使用三层：Spec -> 主 Plan -> 子 Plan/Agent Brief（任务说明）。不要继续拆出多套架构、测试、进度文档；需要长期保留的难以逆转决策使用项目既有 ADR（架构决策记录）约定。

## 业务切片

每个子 Plan 交付一条狭窄但完整的业务能力，而不是一个技术层。它必须：

- 产生用户或业务可观察的结果；
- 有独立验收方式；
- 能在一个全新 Agent 上下文中完成；
- 声明依赖和不可改变的契约；
- 失败后可以独立重试或回滚。

数据库、后端、前端和测试通常是同一切片中的实施步骤。宽范围机械迁移无法垂直切片时，先扩展兼容能力，再分批迁移，最后收紧旧契约（Expand-Migrate-Contract），并保持中间状态兼容。

## 主 Plan 模板

```markdown
# <功能名称> Plan

**Spec：** <链接>
**状态：** 草案 | 已批准 | 执行中 | 完成

## 交付策略
说明为什么采用当前切片和顺序。

## 全局决策与约束
只引用 Spec、ADR 或必要的关键技术决定，不重复业务背景。

## 业务切片
| ID | 业务结果 | 依赖 | 验收摘要 | 状态 | 子 Plan |
|---|---|---|---|---|---|
| P01 | 核心闭环 | 无 | ... | Ready | plans/P01-core-loop.md |

## Frontier（当前可执行任务）
列出依赖已满足、当前可以领取的切片。

## 并行与所有权
说明公共边界、共享文件和不可并行的任务。

## 全局回归与集成
说明哪些核心业务证据必须持续成立，以及何时运行更广验证。

## 自主执行边界
列出 Agent 可自行细化的事项和必须升级审批的变化。

## 风险与恢复
只记录跨切片风险、停止条件和恢复点。
```

## 子 Plan 模板

```markdown
# <ID> <业务切片名称>

**业务结果：**
**依赖：**
**Spec 验收项：**

## 当前实现与约束
记录执行时真实存在的代码边界、接口和相关决策。

## 输入、输出与不变量

## 实施策略
说明关键逻辑、数据流、错误处理和兼容策略。

## 用于固定决策的代码片段
仅在自然语言不足以固定重要决定时出现。

## 执行步骤
步骤围绕形成业务结果，不重复机械的测试模板。

## 验收与回归
列出直接证明本切片和核心闭环的最小证据。

## 失败恢复

## 完成产物
```

## 代码片段纳入条件

当删除代码片段会使不同执行者对重要业务或架构决定产生不同理解时，加入最小片段。适合内容包括：

- 核心公式、决策表或算法骨架；
- 状态机、Reducer、Schema 和关键类型；
- 公共接口及错误语义；
- 性能关键查询、并发或一致性流程；
- 已验证原型中承载结论的部分。

每个片段必须紧邻它固定的决定，并解释适用边界。普通 CRUD、样板代码、完整函数实现和可以由现有项目惯例推导的内容留给执行 Agent。

## 渐进式展开

1. 主 Plan 审批时确定所有业务切片的目标、依赖、验收和自主执行边界。
2. 只详细编写首个 Frontier 中的子 Plan。
3. 上游完成后，基于最新代码展开新的前沿子 Plan。
4. 细化没有改变已批准契约时自动继续。
5. 新增范围、修改验收、公共接口或关键架构时暂停并升级审批。

拆分依据是独立业务结果、依赖、风险，以及单个 Agent 上下文能容纳的范围，不使用固定行数或预估工时。

## 主 Plan 批准条件

- P01 是最小核心业务闭环；
- 每个增强切片都有业务价值和验收摘要；
- 依赖图无循环，Frontier 明确；
- 并行任务不会争用同一公共边界；
- 自治和升级边界清楚；
- 首个子 Plan 可直接执行；
- 用户明确将状态改为“已批准”。
