# 执行状态与恢复

主 Plan 是协调 Agent 维护的执行账本。每个业务切片使用以下状态，英文名称是状态机中的固定值：

| 状态 | 含义 | 允许的下一状态 |
|---|---|---|
| Planned（已规划） | 范围已批准，但依赖或子 Plan 尚未就绪 | Ready、Blocked |
| Ready（可领取） | 依赖、子 Plan、验收、环境和所有权均已就绪 | Claimed、Blocked |
| Claimed（已领取） | 已分配唯一执行者，尚未修改代码 | In Progress、Ready、Blocked |
| In Progress（实施中） | 正在实现 | Implemented、Blocked |
| Implemented（已实现） | 代码或产物已形成，尚未完成业务验证 | Verified、In Progress、Blocked |
| Verified（已验证） | 切片验收和必要回归已通过，证据待归档 | Completed、In Progress |
| Completed（已完成） | 证据已归档，交付结果可被下游依赖 | 仅在回归失败时重新打开 |
| Blocked（受阻） | 缺少业务决定、公共契约、权限、环境或可靠验收 | Planned、Ready |

## Ready（可领取）判定

协调 Agent 只在以下条件全部满足时设置 Ready：

- 所有阻塞依赖是 Completed；
- 当前子 Plan 根据最新代码展开；
- 输入、输出、不变量和验收方式可执行；
- 公共接口和 Schema 已固定或由本切片独占；
- 文件、模块和运行资源所有权无冲突；
- 凭据、工具和环境可用；
- 没有未决业务解释。

标签不是事实。每次调度前重新检查这些条件。

## 主 Plan 状态表

```markdown
| ID | 业务结果 | 依赖 | 状态 | 执行者 | 子 Plan | 证据/阻塞 |
|---|---|---|---|---|---|---|
| P01 | 生成正确基础报表 | 无 | In Progress | agent-a | plans/P01.md | evidence/P01/ |
```

只有协调 Agent 更新此表。执行 Agent 通过结果包返回状态和证据，不直接竞争写入。

## 中断恢复

按顺序重建状态：

1. 读取已批准 Spec、主 Plan 和当前子 Plan；
2. 检查 Git diff、提交、工作区和运行进程；
3. 检查证据文件及其输入版本、命令和时间；
4. 对照状态表识别不一致；
5. 将没有业务证据的 Completed 降回 Implemented；
6. 对可能重复的操作确认幂等性或恢复点；
7. 重新计算 Ready 前沿和所有权；
8. 从最后一个可证明的检查点继续。

不要通过清空工作区或重跑整个计划来简化恢复。无法判断归属的修改先隔离并记录，再继续不冲突的任务。

## 回归失败

下游切片破坏已完成业务证据时：

- 将下游切片退回 In Progress；
- 若根因是上游契约错误，重新打开相关上游切片；
- 暂停依赖受影响证据的前沿；
- 保持无关前沿继续；
- 修复后重新生成被影响的证据链。
