# Agent Brief（任务说明）与并行所有权

每个执行 Agent 使用全新、最小、自包含的任务说明。协调 Agent 必须把下面的模板填好后传给子代理,**不要在子代理外部展开实现细节**。

## 标准 Agent Brief 模板

```markdown
## 任务
- 切片 ID：<P01 / P02 ...>
- 业务结果：<一句话描述本切片要让什么业务场景通过>
- 范围：<明确列出要做的事,以及明确不做的事>

## 事实来源（只读链接，不要复制内容）
- Spec：<路径>#<章节>
- 主 Plan：<路径>
- 子 Plan：<路径>
- ADR / 公共契约：<路径>
- 相关代码模块：<路径列表,只读>

## 依赖产物
<已完成上游的接口签名、数据契约、版本号、Schema 和证据路径>

## 所有权
**允许修改：** <文件路径、模块、专属数据或资源>
**只读：** <共享接口、依赖模块、冻结契约>
**禁止修改：** <Spec、主 Plan、其他切片所有权、冻结契约文件>

## 完成定义（必须全部满足）
- 业务验收：<具体业务场景应表现为什么>
- 代码层验证：<运行哪些命令,预期输出>
- 核心业务回归：<必须重新验证的已通过切片>
- 证据：<保存到 evidence/<ID>/ 的文件清单>
- 返回：<修改摘要、文件列表、命令、证据路径、剩余风险>

## 升级条件（命中任一条立即停下回报，不自行决定）
- 业务规则 / 不变量 / 验收标准与已批准 Spec 不一致
- 需要改变公共接口、Schema、迁移路径或关键架构
- 缺少凭据、外部权限或不可恢复操作授权
- 业务口径存在多种合理解释,无法用现有证据区分
- 发现系统性风险,超出本切片授权

## 不要做
- 不要修改主 Plan、Spec 或其他切片所有权
- 不要跳过证据保存
- 不要用全量测试或代理数量替代业务证据
- 不要在遇到歧义时自行选择一种业务解释继续推进
```

## 传递原则

传递权威文件路径和切片必需的最小摘要,**不复制整段会话或完整计划**。子代理必须先读取真实文件,再执行任务。

如果切片需要子代理内部继续 spawn 下一层代理,必须在 Brief 中显式声明"本切片可能分 N 个子任务",否则子代理不应自行展开。

## 并行判定

两个切片只有同时满足以下条件才可并行：

- 没有直接或间接顺序依赖；
- 不修改同一公共接口、Schema 或迁移；
- 不竞争同一文件、数据库、端口、浏览器或外部配额；
- 一个切片的判断不会改变另一个切片的验收；
- 结果可以分别验证后再集成。

如果 P02 和 P03 都需要修改结果 Schema：

1. 不要直接并行实现；
2. 创建或展开一个契约冻结切片；
3. 比较双方需求并固定兼容、迁移和所有权；
4. 契约 Completed 后重新计算前沿；
5. 下游基于冻结契约并行。

## 协调 Agent 独占内容

- Spec 和主 Plan 状态；
- 跨切片公共契约；
- 执行者分配和文件所有权；
- Frontier（当前可执行任务）；
- 最终证据索引和交付报告。

执行 Agent 发现这些内容需要变化时只提交提案，不直接修改。

## 协调 Agent 自检清单

每次 spawn 子代理前确认：

- [ ] 子代理只读链接了必要的 Spec / Plan / 契约
- [ ] 所有权边界明确到文件路径级别
- [ ] 升级条件是可观察信号,不是空话
- [ ] 返回契约包含证据路径和剩余风险
- [ ] 子代理 prompt 中包含 `[升级条件]` 字面提示
