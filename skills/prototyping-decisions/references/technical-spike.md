# 技术可行性 Spike

只有官方资料、现有代码和普通调查无法回答运行行为时才使用，例如 SDK 的真实错误语义、协议兼容、特定数据分布下的算法行为或 sandbox 中的外部系统限制。

## 先决条件

- 写明文档仍未回答的具体问题；
- 获得 sandbox、最小权限凭据或本地替代物；
- 禁止使用生产写权限；
- 固定时间、请求次数、成本和停止条件。

## 工件

只实现一个调用或数据路径，保存输入、环境、实际响应、限制和可复现命令。不要顺便建立完整客户端、重试框架、持久化、部署或监控。

外部系统能力应先调用 `$researching-decisions` 查官方文档。没有文档和凭据时，写不可运行的接入壳不能形成证据，应停止并申请所需资料。

## 结论

区分“已证明”“在当前 sandbox 中观察到”和“仍是假设”。结果可以输入 `$designing-business-architecture` 或 Spec，但一次 spike 不自动批准生产供应商、容量或长期架构。
