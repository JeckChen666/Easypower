# UI 交互原型

适用于页面结构、信息层级、交互状态或高频工作流需要在真实产品语境中比较的情况。

## 优先嵌入现有页面

保留真实导航、侧边栏、数据密度、权限上下文和响应式约束，只替换被比较的渲染区域。仅在没有合理宿主页面时建立显式 prototype 路由。

默认制作 2–3 个结构明显不同的方案，最多 4 个。差异应体现在布局、信息优先级、操作顺序或主要交互方式，而不是颜色和装饰。所有方案使用相同数据和任务，例如“切换到某组织、月份和产品并确认当前条件”。

## 切换与观察

使用 URL 参数、分段控件或开发环境切换器保持方案可分享、可重载。切换器必须与候选 UI 视觉区分，并在生产构建中不可访问。

比较：完成高频任务的步骤、当前状态可见性、错误恢复、空间占用、窄屏行为和与现有页面的一致性。只读数据优先；需要操作时写入 stub 或内存状态。

## 清理

用户选择后，将批准的信息层级和交互规则回写 Spec。删除切换器、未选方案和 prototype 路由；胜出方案按正式组件、权限、错误处理、可访问性和验证要求重新实现。
