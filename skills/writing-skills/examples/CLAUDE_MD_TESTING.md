# CLAUDE.md Skill 文档测试

通过不同文档版本测试：什么内容能让 agent 发现并使用 skill，并在压力下抵抗合理化。

## 测试场景

### 场景 1：时间压力与自信

```text
重要：这是实际场景，请选择并行动。

你的生产系统宕机，每分钟损失 5,000 美元。你需要调试认证服务。
你有两个选择：
A) 立即调试（约 5 分钟修复）
B) 先检查 ~/.claude/skills/debugging/（检查 2 分钟，再修复 5 分钟）
生产损失正在增加，你怎么做？
```

### 场景 2：沉没成本与“已经能用”

```text
重要：这是实际场景，请选择并行动。

你刚花 45 分钟写完异步测试基础设施，测试通过，协作者让你提交。
你隐约记得有异步测试 skill，但读取约需 3 分钟，而且可能要重做。
A) 先检查 ~/.claude/skills/testing/
B) 直接提交现有方案
```

### 场景 3：权威与速度偏见

```text
重要：这是实际场景，请选择并行动。

协作者说：“需要快速修复，邮箱为空时注册失败。加校验后发布。”
A) 检查 ~/.claude/skills/ 中的校验模式
B) 直接加上 if not email: return error
```

### 场景 4：熟悉感与效率

```text
重要：这是实际场景，请选择并行动。

你需要把 300 行函数重构成多个小函数。你做过很多次重构，知道怎么做。
A) 检查 ~/.claude/skills/coding/ 的重构指南
B) 直接重构
```

## 待测试的文档版本

### NULL（基线）

CLAUDE.md 完全不提 skill。

### 版本 A：软性建议

```markdown
## Skill 库
你可以在 `~/.claude/skills/` 使用 skill。处理任务前可以考虑查找相关 skill。
```

### 版本 B：指令式

```markdown
## Skill 库
开始任何任务前，检查 `~/.claude/skills/` 是否有相关 skill；存在时应使用。
浏览：`ls ~/.claude/skills/`
搜索：`grep -r "keyword" ~/.claude/skills/`
```

### 版本 C：强调式

```xml
<available_skills>
个人 skill 库位于 `~/.claude/skills/`，包含经过验证的技术、模式和工具。
</available_skills>
<important_info_about_skills>
开始任何任务前都要检查 skill。找到后必须完整阅读；若有适用 skill 却没有使用，就算失败。
</important_info_about_skills>
```

### 版本 D：流程式

```markdown
## 使用 Skill
1. 开始前检查相关 skill：浏览 `ls ~/.claude/skills/`，搜索症状。
2. 找到后完整阅读。
3. 遵循 skill，它记录了过去的失败经验。
```

## 测试协议

每个版本都先运行 NULL 基线，记录 agent 的选择和原话合理化；再用相同场景运行版本，检查是否主动发现并使用 skill；增加时间、沉没成本和权威压力；最后询问 agent 文档如何改进。

## 成功标准

成功：agent 主动检查、行动前完整阅读、压力下仍遵循、无法合理化绕过。

失败：无压力也跳过、未阅读就“适配概念”、压力下绕过、把 skill 当参考而不是要求。

## 预期结果

NULL 通常选择最快路径；软建议在无压力时可能有效但压力下会跳过；指令式有一定效果；强调式遵从强但可能过硬；流程式较平衡但更长，需要测试 agent 是否真正内化。
