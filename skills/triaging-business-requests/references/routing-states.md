# 分流状态协议

## 单一当前状态

| 状态 | 准入条件 | 下一动作 |
|---|---|---|
| Needs Evidence | 缺少验证主张或影响所需的最小证据 | Agent 先调查，再提出少量具体补充项 |
| Needs Business Decision | 事实足够，但业务口径、价值、范围或风险接受者未确认 | 每次推进一个业务决定 |
| Ready for Planning | 业务问题、边界、验收依据和阻塞决定足够明确 | 写 Business Brief，交规划 Skill |
| Route to Existing Capability | 已有能力满足目标，缺口在入口、权限、配置或使用方式 | 提供可验证路径，处理真实可用性缺口 |
| Duplicate | 活动请求或已批准工作已经覆盖同一业务结果 | 链接权威条目，保留新证据 |
| Active Incident | 高影响业务失败正在发生，需要立即止损 | 调用诊断 Skill，不等待普通队列 |
| Deferred | 请求有价值，但依赖、时机或容量条件暂不满足 | 记录恢复条件和复查触发器 |
| Rejected | 与业务方向、风险边界或持久决定冲突 | 记录可解释依据和重新考虑条件 |

原 tracker 的标签可以映射到这些语义，但不是 Easypower 的权威状态机。存在冲突标签时先报告冲突，不自行猜测哪个有效。

## 优先级判断

使用可解释维度，不使用没有依据的加权总分：

- 业务严重度：阻止关键工作、产生错误决定、财务/安全/合规风险或便利性改进；
- 影响范围：单人、单租户、某类用户或全体；
- 频率与持续时间：一次、间歇、重复或持续；
- 时间敏感性：是否有真实业务窗口、法规日期或损失增长；
- 替代路径：是否可行、成本和风险如何；
- 证据置信度：已复现、有运行证据、仅报告或纯推测；
- 不处理后果：损失、风险、运营成本或机会影响。

输出推荐优先级时附适用前提。例如“若财务错报仍在影响本月结账，则为立即处理；当前缺少租户和时间范围，影响规模未知”。

## 外部变更门

先输出建议：类别、状态、理由、优先级、准备发布的评论/标签/关闭动作。用户明确批准后才应用外部变更。若用户一开始已明确要求执行具体变更且目标无歧义，可以直接操作，但仍需报告实际结果。

延期不同于拒绝。延期必须有可观察的恢复条件；拒绝应引用长期业务理由或已批准决定。已经实现不同于拒绝，不要把已有能力写入拒绝知识库。
