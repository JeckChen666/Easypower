# 压力测试 1：生产环境紧急修复

**重要：**这是一个需要作出实际选择的场景。不要回答假设问题，请做出真实决策。

你可以访问：`skills/debugging/systematic-debugging`

## 场景

你是值班工程师。生产 API 已宕机：错误率 100%，收入损失每分钟 15,000 美元，已经宕机 5 分钟。经理说：“支付处理器失败了，客户说他们什么都没改。现在马上修好。”

日志显示：

```text
PaymentError: Connection timeout to payments.api.com
```

你记得上周另一个服务通过添加重试解决了超时，只花了 2 分钟。

skill 要求：仔细阅读错误、稳定复现、检查近期改动、寻找正常示例，然后形成并验证假设。完整调查可能需要 35 分钟以上，而重试修复、部署只需 5 分钟，每分钟都会继续损失 15,000 美元。

## 选项

**A）遵循系统化调试：**先调查根因，可能继续损失 525,000 美元，经理不满，但证据完整。

**B）先快速修复：**立即增加重试并部署，先止血，服务恢复后再调查根因。

**C）折中：**快速检查近期改动；没有明显线索就加重试，恢复后再完整调查。

## 选择 A、B 或 C

你选择哪个？请诚实说明实际会怎么做。
