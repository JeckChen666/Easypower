# Frontier（决策前沿）与恢复协议

## 状态与 Frontier

| 状态 | 含义 |
|---|---|
| Planned（已规划） | 问题已明确，但依赖尚未解决 |
| Ready（可领取） | 依赖已解决，可立即领取 |
| Claimed（已领取） | 一个执行者已登记，避免重复工作 |
| Blocked（受阻） | 需要外部权限、输入或用户参与才能继续 |
| Resolved（已解决） | 结论、依据、范围和批准已经记录 |
| Dropped（已取消） | Destination 或前序决定使该问题失效或超出范围 |

前沿只包含 `Ready` 且未被领取的票据。标签不是事实；每次领取前检查依赖票据是否真的 Resolved、输入是否可用、决策者是否在场，以及另一会话是否已领取。

多个 Agent 可以并行处理互不依赖、不会竞争同一权威文件的 Research 或 Prerequisite。协调 Agent 独占主地图更新；其他 Agent 返回结论包，不同时改写地图。Business、Domain、Prototype 和 Architecture 中需要用户决定的部分不能以并行 Agent 的多数意见关闭。

## 中断恢复

新会话按以下顺序恢复：

1. 完整读取主地图的 Destination、已决事项、Frontier 和下一步入口；
2. 检查处于 Claimed 的票据、执行者和最后证据；
3. 只打开拟领取票据及其直接依赖结论；
4. 将没有实际活动或结果的过期 Claim 恢复为 Ready，并保留原因；
5. 根据真实依赖重新计算前沿；
6. 从最后一个有依据的已决结论继续，不依赖聊天摘要。

不要因中断重新生成整张地图，也不要批量打开所有票据来“恢复上下文”。

## 解决后的地图维护

票据解决后：

- 在票据记录决定、适用范围、依据、批准与路线影响；
- 在主地图添加一行名称、链接和结论摘要；
- 删除已解决票据的 Claim，并从 Frontier 移除；
- 把已经能够精确提问的 Fog 转成 Decision Ticket；
- 删除被结论消除的未知方向；
- 将失效票据标为 Dropped，不伪造为已解决；
- 重新写下一会话入口。

若结论改变已批准 Destination 或范围，停止更新下游并请求用户重新批准。旧地图需要保留时标为 Superseded 并链接新地图，不在原记录上悄悄改写历史。
