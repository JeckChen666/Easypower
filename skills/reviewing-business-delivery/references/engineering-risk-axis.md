# 工程风险轴

从改动最可能造成的业务影响出发选择检查项，不机械遍历清单。

| 风险 | 重点证据 |
|---|---|
| 正确性 | 边界、错误路径、数据和状态转换、调用方假设 |
| 权限与安全 | 身份来源、服务端授权、租户隔离、秘密和输入边界 |
| 数据生命周期 | Schema、迁移幂等、备份、双写、校验、回滚和删除时机 |
| 并发与一致性 | 原子性、幂等、重复消息、竞态和未知状态 |
| 兼容性 | 公共接口、消费者、版本协商、旧数据和部署顺序 |
| 性能与成本 | 代表性负载、查询计划、缓存、资源转移和退化保护 |
| 恢复与运维 | 部分失败、重试、停止、恢复点、观察指标和告警 |
| 可维护性 | 业务规则是否局部、接口是否过宽、改动是否散落 |

## 判断规则

- 只报告可以从代码、数据流、调用方或证据支持的风险；
- 给出具体触发场景和业务影响，不写“错误处理可以更好”；
- 通用代码气味只是线索，只有当前影响值得修复时才报告；
- 仓库明确约定覆盖个人偏好；
- formatter、lint 或类型检查已可靠捕获的问题不重复人工列出；
- 测试缺口只有在缺少某项关键风险证据时才是 finding，不追求覆盖率数字。

## 高风险变化

金额、权限、数据迁移、公共 Schema、外部副作用、并发状态和不可逆操作默认需要检查失败与恢复路径。业务正常路径通过不能降低这些风险的严重度。
