# BI 报表执行示例

已批准主 Plan 包含：

```text
P01 核心报表闭环
  ├─ P02 计算性能优化
  ├─ P03 筛选排序
  └─ P04 结构化存储
```

## 首次前沿

只有 P01 满足依赖。协调 Agent 展开 `plans/P01-core-loop.md`，分配唯一所有权并执行。代码生成但黄金结果尚未比较时，P01 是 Implemented，不是 Completed。

黄金样本、边界样例和核心结果回归通过后，证据保存到 `evidence/P01/`，P01 才进入 Completed。

## 第二次前沿

协调 Agent 检查 P02-P04，不直接相信原先的 Ready 标记：

- P02 需要修改计算输出结构；
- P04 需要建立持久化 Schema；
- P03 只消费当前稳定查询接口。

P02 与 P04 存在公共契约争用，因此先展开 `P05-freeze-result-contract.md`。P03 在确认只读现有契约后可以独立执行。P05 完成后，P02 与 P04 基于冻结契约并行。

## 无人值守阻塞

P04 执行中发现“保存结果快照”与“保存原始数据并支持完整重放”都有合理业务解释。执行 Agent 返回提案，协调 Agent 将 P04 标为 Blocked，并暂停依赖 P04 的历史查询。

P02 和 P03 不依赖该决定，继续执行。最终报告列出：

- P01、P02、P03 的业务证据；
- P04 的两种解释、存储和迁移影响；
- 用户只需回答的决定；
- P04 的代码现场和恢复入口。

用户回来后批准一种解释，更新 Spec/主 Plan，再基于最新代码重新展开 P04，而不是重跑整个计划。
