# 风险验证、失败与恢复

## 选择验证

先问“什么证据能直接证明该业务结果”，再选择命令和工具。

| 变化类型 | 最少但充分的验证 |
|---|---|
| 文档、文案、低风险配置 | 格式、差异或针对性检查 |
| 独立业务切片 | 切片验收 + 核心闭环回归 |
| 复杂公式、金额、权限、状态 | 代表性样例 + 关键边界 + 稳定业务接口验证 |
| 公共接口、Schema、迁移 | 受影响消费者 + 兼容/回滚 + 必要集成验证 |
| 性能增强 | 结果等价 + 固定输入和环境下的前后基准 |
| 跨模块或影响范围不明 | 构建、相关集成和更广回归；必要时完整测试集 |

不要固定要求每个切片都使用独立评审代理、全量测试或所有测试层。高风险业务可以增加独立复核，低风险变更保留直接证据即可。

## 证据包

每个 Completed 切片在 `evidence/<ID>/` 或项目约定位置留下：

- 输入、数据版本或复现条件；
- 期望业务结果；
- 实际结果或可检查产物；
- 执行命令、环境和关键输出；
- 核心闭环回归结果；
- 已知限制和未覆盖风险。

测试日志可以成为证据，但不能替代业务结果。证据应让新上下文能够独立判断，而不依赖执行者的结论。

## 失败分类

| 类型 | 处理 |
|---|---|
| 局部实现错误 | 调用 `$diagnosing-business-failures` 建立稳定业务反馈并在当前授权内修复 |
| 已批准范围内的技术选择失败 | 比较等价替代方案，更新子 Plan 后继续 |
| 业务口径多解 | Blocked，记录选项和影响，等待用户 |
| 公共接口或关键架构必须变化 | Blocked，暂停受影响依赖，升级审批 |
| 外部服务或凭据不可用 | 保存现场和恢复命令，继续独立前沿 |
| 验收工具不可靠 | 不得标记 Verified，先修复证据链 |
| 不可恢复或生产操作缺授权 | 停止，不以无人值守授权替代专项授权 |

## 阻塞记录

```markdown
## <ID> 阻塞
**事实：**
**无法自行决定的原因：**
**候选方案及业务影响：**
**受影响切片：**
**仍可继续的前沿：**
**恢复入口：**
```

不要因为一个 Blocked 切片停止所有任务，也不要为了保持进度替用户选择业务解释。
