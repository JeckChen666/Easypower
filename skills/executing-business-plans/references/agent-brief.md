# Agent Brief（任务说明）与并行所有权

每个执行 Agent 使用全新、最小、自包含的任务说明：

```markdown
## 任务
<切片 ID 和业务结果>

## 事实来源
- Spec：<路径和相关章节>
- 主 Plan：<路径>
- 子 Plan：<路径>
- ADR/公共契约：<路径>

## 依赖产物
<已完成上游的接口、数据、版本和证据>

## 所有权
**允许修改：** <文件、模块、专属数据或资源>
**只读：** <共享接口和依赖>
**禁止修改：** <Spec、主 Plan、其他任务所有权和冻结契约>

## 完成定义
- <业务切片验收>
- <核心业务回归>
- <需要返回的代码、产物和证据>

## 升级条件
<必须停止并返回协调 Agent 的变化>

## 返回结果
修改摘要、实际文件、运行命令、业务证据、剩余风险和建议状态。
```

传递权威文件链接和任务所需摘要，不复制整段会话或所有计划。Agent 必须先读取真实文件，再执行任务。

## 并行判定

两个切片只有同时满足以下条件才可并行：

- 没有直接或间接顺序依赖；
- 不修改同一公共接口、Schema 或迁移；
- 不竞争同一文件、数据库、端口、浏览器或外部配额；
- 一个切片的判断不会改变另一个切片的验收；
- 结果可以分别验证后再集成。

如果 P02 和 P03 都需要修改结果 Schema：

1. 不要直接并行实现；
2. 创建或展开一个契约冻结切片；
3. 比较双方需求并固定兼容、迁移和所有权；
4. 契约 Completed 后重新计算前沿；
5. 下游基于冻结契约并行。

## 协调 Agent 独占内容

- Spec 和主 Plan 状态；
- 跨切片公共契约；
- 执行者分配和文件所有权；
- Frontier（当前可执行任务）；
- 最终证据索引和交付报告。

执行 Agent 发现这些内容需要变化时只提交提案，不直接修改。
