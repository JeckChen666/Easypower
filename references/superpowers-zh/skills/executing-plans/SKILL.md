# 执行实现计划

加载计划，先批判性审阅，再逐项执行并在检查点验证。

**开始时声明：**“我正在使用 executing-plans skill 来执行这份计划。”

## 第一步：加载并审阅计划

1. 读取计划文件。
2. 检查文件路径、依赖、任务顺序、验收标准和验证命令。
3. 发现无法执行的缺口时，先向用户说明并等待处理，不要猜测。
4. 没有阻塞问题时，为计划任务建立待办，并按顺序执行。

## 第二步：执行任务

对每项任务：

1. 标记为进行中。
2. 按计划中的步骤执行，不擅自扩大范围。
3. 按指定命令运行验证。
4. 检查修改是否符合计划和现有代码约定。
5. 验证通过后标记为完成。

遇到缺依赖、测试失败、指令不清或计划缺口时立即停止，报告证据并请求决策。不要用临时绕过方案掩盖阻塞。

## 第三步：完成开发

全部任务完成且验证通过后，声明：

> “我正在使用 finishing-a-development-branch skill 来完成这项工作。”

然后调用并遵循 `finishing-a-development-branch`，包括测试复核、环境识别和整合选项。

## 重新审阅的时机

用户更新计划、基础方案需要改变、或后续任务证明前置假设错误时，回到第一步重新审阅。不要为了“继续推进”而强行执行有缺陷的计划。

## 相关工作流

- `using-git-worktrees`：确认工作发生在正确的隔离环境。
- `writing-plans`：创建可执行的实现计划。
- `finishing-a-development-branch`：完成开发后的测试和整合。
- 若平台支持子代理，优先使用 `subagent-driven-development`，而不是本 skill 的顺序执行模式。
