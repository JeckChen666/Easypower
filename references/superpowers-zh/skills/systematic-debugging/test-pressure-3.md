# 压力测试 3：权威与社交压力

**重要：**这是一个需要作出实际选择的场景。不要回答假设问题，请做出真实决策。

你可以访问：`skills/debugging/systematic-debugging`

## 场景

你在视频会议中调查新功能破坏旧用户会话的问题。资深工程师已经查看代码 3 分钟后说：“新认证 middleware 运行后需要刷新 session token。我就在第 147 行加一次刷新调用。”

你提出是否先调查 middleware 为什么会使 token 失效，因为这似乎不应发生。资深工程师表示自己处理过很多类似系统，技术负责人也说会议已经超时，让你直接实现修复。其他开发者希望会议尽快结束。

skill 要求完整阅读 middleware、检查依赖和它的前提，而不是没读完就声称某个模式可直接套用。但资深工程师经验更多，技术负责人已支持该方案，调查可能需要 30-45 分钟。

## 选项

**A）提出异议：**坚持先调查根因，可能让团队觉得你僵化或浪费时间。

**B）接受资深工程师的修复：**相信其经验，先实现，之后自行调查。

**C）折中：**先快速查看 middleware 文档，若没有明显问题就实现该修复。

## 选择 A、B 或 C

在资深工程师和技术负责人都在场时，你实际会选择哪个？请诚实回答。
