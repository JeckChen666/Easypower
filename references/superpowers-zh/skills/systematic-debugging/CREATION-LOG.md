# 创建记录：系统化调试 Skill

这是提取、组织和加固关键 skill 的参考记录。

## 来源材料

从 `~/.claude/CLAUDE.md` 提取调试框架：调查 -> 模式分析 -> 假设 -> 实现四阶段流程；核心要求是始终寻找根因，绝不只修复症状；规则用于抵抗时间压力和自我合理化。

## 提取决策

**保留：**完整四阶段框架、所有规则、反快捷方式语言、每阶段的具体步骤。

**去除：**项目特定上下文、重复规则、将叙事压缩为原则。

## 按 skill 创建规范组织

1. 丰富的适用条件和反模式；
2. 具体的技术流程；
3. “根因”“症状”“变通方案”“调试”“调查”等触发关键词；
4. “修复失败后重新分析”的流程图；
5. 可扫描的分阶段清单；
6. 明确说明不能做什么的反模式章节。

## 加固元素

使用 ALWAYS/NEVER、即使更快、即使看起来很着急、停止并重新分析等措辞，抵抗压力下的合理化。通过强制第一阶段、单一假设规则、首次修复失败时的明确动作和反模式章节，防止跳过调查。

## 测试方法

使用 `testing-skills-with-subagents` 中的方法进行了四类验证：无压力的学术问题、时间压力下的快速修复、复杂多层失败和第一次修复失败。各测试均完成完整调查，没有发现合理化绕过流程。

## 迭代

增加 TDD 引用，说明“最简单代码”和“追踪根因”是不同目标，避免两种方法混淆。

## 最终结果

该 skill 明确要求调查根因，能抵抗时间压力，提供每阶段的具体步骤，公开展示反模式，并经过多种压力场景验证。

## 关键经验

最有效的加固是列出那些当下看似合理的快捷方式。当 agent 想“先加一个快速修复”时，看到同样模式被明确标为错误，会增加停下来调查的阻力。

## 使用示例

遇到缺陷时：读取 skill 概述，执行第一阶段调查；想跳过时查看反模式；完成所有阶段并确认根因。通常投入 5-10 分钟，却能避免反复修补症状浪费数小时。
