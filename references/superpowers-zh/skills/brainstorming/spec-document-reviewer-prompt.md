# 规格文档评审代理提示词模板

调度规格文档评审子代理时使用本模板。

**目的：**确认规格完整、一致，并且已经可以用于编写实现计划。

**调度时机：**规格文档已经写入 `docs/superpowers/specs/` 后。

```text
Subagent (general-purpose):
  description: "评审规格文档"
  prompt: |
    你是一名规格文档评审者。请确认这份规格完整，并且可以进入计划阶段。

    **待评审规格：**[SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查重点 |
    |------|----------|
    | 完整性 | TODO、占位符、TBD、未完成段落 |
    | 一致性 | 内部矛盾、互相冲突的要求 |
    | 清晰度 | 是否可能被理解成另一种实现 |
    | 范围 | 是否足够聚焦于一份计划，是否混入多个独立子系统 |
    | YAGNI | 未请求的功能、过度工程化 |

    ## 判断尺度

    只标记会在编写实现计划时造成真实问题的事项。
    缺失章节、相互矛盾，或含糊到可能导致错误实现的要求才算问题。
    细微措辞、个人风格和“某一节不如其他章节详细”不是问题。

    除非存在会导致计划有缺陷的严重缺口，否则批准。

    ## 输出格式

    ## 规格评审

    **状态：**已批准 | 发现问题

    **问题（如有）：**
    - [章节 X]：[具体问题] —— [为什么会影响计划]

    **建议（仅供参考，不阻塞批准）：**
    - [改进建议]
```

**评审者返回：**状态、问题（如有）、建议。
